✨ 六大通用模式

背完 52 条后掌握这 6 个模式,就能自己写出同水平的提示词。

1 · 描述结果,而不是步骤

说出你想要什么,让 Claude 自己找文件,无需指名路径。

add rate limiting to the public API and make sure existing tests still pass给公开 API 加上限流,并确保现有测试仍通过

2 · 给它自查手段

同一条提示词里要求运行、测试、对比或验证,让它迭代而非试一次就停。

write the migration, run it against the dev database, and confirm the schema matches写迁移脚本,在开发库上执行,确认 schema 一致

3 · 指向参照物

点名现有文件、测试或模式,新代码就和你已有的一致。

add a settings page that follows the same layout as the profile page加一个设置页,布局与个人资料页保持一致

4 · 给出可测量的目标

涉及性能或覆盖率时,给指标和阈值,「完成」才有定义。

get the bundle size under 200KB and show me what you removed把包体积降到 200KB 以内,并列出你删了什么

5 · 直接给工件

把报错、日志、截图、plan 输出粘进提示词,或用 @ 引用文件。

why is the build failing? @build.log构建为什么失败?@build.log

6 · 说明答案的形式

点名格式、长度或受众,解释才合你的用途。

explain how the payment retry logic works as an HTML page with a diagram, then open it in my browser用一页带图表的 HTML 解释支付重试逻辑,然后在我的浏览器里打开

🎯 背诵建议

  • 背诵路线:先背 5 条 ★ 起点(约 10 分钟),再按「发现 → 构建 → 运营 → 设计 → 交付」每天 8~10 条,一周背完。
  • 记骨架不记全文:每条只需记住「动词 + 槽位 + 约束 / 验证」,如 write tests for X, run them, and fix any failures。
  • 中英等效:Claude Code 对中英文提示词效果等同;英文原句在团队协作、写技能、写文档时更通用。
  • 落地闭环:背熟 → 用进日常开发 → 高频提示词沉淀为 /技能 或 CLAUDE.md 规则(见第 35、49、52 条)。
