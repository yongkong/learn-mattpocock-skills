Lesson 0003 · 实战

实战:跑通主流程前三站

地图(0001)和四台发动机(0002)都认识了。这课没有新知识——它是一份飞行清单,带你在本仓库把 /grill-with-docs → /to-spec → /to-tickets 真正跑一遍。跑完,前三站就从「知道」变成「做过」。

练习题已经选好:给这个课程工作区做一个真实有用的小功能——课程主页(course-homepage):一个 index.html,列出全部课程与速查文档、标注学习进度,点击直达。它够小(一个会话能装下)、够真实(以后真的会用到)、又够完整(能打通每一层)。

想换成自己工作里的真实想法?完全可以,流程一字不差——把想法直接发给老师(对话里的 agent)即可。

起飞前检查

  • ✅ skills 已安装(mattpocock-skills 插件)
  • ✅ 本仓库已跑过 /setup-matt-pocock-skills:issue tracker = local markdown(.scratch/),triage 标签为默认五件套——这两样正是 to-spec 和 to-tickets 的前置条件
  • ✅ 想法已选定(课程主页,或你自己的)

第一站:/grill-with-docs(访谈 + 沉淀)

你敲什么/grill-with-docs(或直接对老师说「开始实战课」)
agent 会做什么按 frontier 分轮提问:每轮一批编号问题,每题附推荐答案;能查代码自己查,只有决策问你
交接物达成共识的设计 + 顺手更新的 CONTEXT.md 词条 / ADR(如有够格的)
你的验收点结束标志是 frontier 清空且你确认共识;结束后看一眼 CONTEXT.md 是否多了词条

第二站:/to-spec(综合成文)

你敲什么/to-spec
agent 会做什么不再问你问题,只综合已有对话;探索仓库;提出测试 seams 请你确认(优先已有 seam、用最高 seam、越少越好);按模板写 spec
交接物.scratch/course-homepage/spec.md,贴 ready-for-agent 标签
你的验收点user stories 是否覆盖全面;spec 里是否偷跑了实现细节(不该出现具体文件路径和代码片段——过时太快)

第三站:/to-tickets(拆成工单)

你敲什么/to-tickets(可带上 spec 路径)
agent 会做什么把 spec 拆成竖切(tracer bullet)工单,声明 blocking 边;发布前拿三个问题考你:粒度对吗?边对吗?要合并/拆分吗?
交接物.scratch/course-homepage/issues/01-*.md、02-*.md……一票一文件,按依赖顺序编号,每张贴 ready-for-agent
你的验收点每张工单是否独立可演示;编号顺序是否 = 依赖顺序(blocker 在前);frontier 是否清晰(blocker 全完成的随时可开工)

降落与复盘

三站跑完后,回到对话说「复盘」:老师陪你逐份查看 .scratch/ 里产出的 spec 和工单,对照 spec 与工单速查挑毛病——格式跑样、竖切不竖、blocking 边画错,都是这一课最有价值的收获。

想继续飞?下一站是 /implement:挑一张无阻塞的工单(工作 frontier),它会内部驱动 /tdd(red → green,seam 上见)并在收尾自动跑 /code-review——那已经是另一课的内容了。

练一练:飞行手册考核

起飞前先过一遍这 7 题——全部关于「每一站你会遇到什么、该做什么」。

速查与提醒

飞行中迷路就开这两份:spec 与工单长什么样(交接物格式)和 全局地图(情境路由)。

卡住了就问老师。无论是对问题答不上来、觉得某站的输出不对劲,还是想中途换想法——对话里直接说。
