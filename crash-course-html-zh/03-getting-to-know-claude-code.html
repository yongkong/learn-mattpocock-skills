引言（Intro）

在这门课程里，我将主要使用 Claude Code 作为我的 agent（智能体），用它来推进课程、演示各种操作，并向你展示 agent 的一般工作方式。

我这么做，是因为它是一款非常流行的 harness（挽具 / 承载工具），你可能自己也用过，而且它也是我个人目前用得最多的一个。

**不过，本课程是 harness 无关的。**只要能在 CLI 里运行，你可以任选自己喜欢的 harness。挑一个最适合你的工具就好。

可选的预备章节（An Optional Primer Section）

对于从未用过 coding harness 的朋友，或者只是想把 Claude Code 用得更透彻的朋友，我准备了一个可选的预备入门章节，让你在正式开始前先掌握基础。

它会帮你打好底子，让你在开始本课程之前，把关于你的 agent 需要了解的事情都了解清楚。

而如果你已经熟练使用自己选的 harness，多半还是能从中学到一些技巧——因为我讲的不只是基础，里面还混着一些进阶内容。

干得漂亮，我们下一节见。

管理你的 Claude Code session（Managing Your Claude Code Session）

请确保你已经把 Claude Code 安装配置好、随时能用。如果还没完成，请回到 Before We Start 部分，跟着设置步骤把它装到你的系统上。

整门课程我们都会在 VS Code 里运行 Claude。Claude 与 VS Code 本身的关系我们稍后会讲，但现在直接在集成终端（integrated terminal）里运行它完全没有问题。

打开 Claude Code 与输入框（Opening Claude Code And The Input Box）

先在终端里启动 Claude，然后把缩放比例稍微调大一点，看起来更清楚。

VS Code 集成终端中启动了 Claude Code，显示聊天界面

你会看到一个底部带着巨大文本框的 UI。你所有的 prompt（提示词）都在这里输入。

你的第一条消息（Your First Message）

我们从简单的开始。你可以对 Claude 说任何话，就像你用过的任何聊天应用一样。

hello, how are you?

agent 会处理你的消息并自然地回应。这种熟悉的类聊天界面让你很容易上手。

Claude Code 对问候做出友好回应

终端设置与多行输入（Terminal Setup And Multi-Line Input）

在继续之前，有一条重要命令要运行：/terminal-setup。

/terminal-setup

输入正斜杠，然后从自动补全列表里找到 terminal setup。找对了，命令会变成好看的淡紫色。

自动补全菜单中以淡紫色高亮的 /terminal-setup 命令

按 Enter 运行它。

这条命令会为你配置键位绑定，专门针对 Shift+Enter。取决于你的操作系统，你可能需要手动运行它（比如在 Windows Subsystem Linux 上），但大多数用户直接运行一下就万事俱备。

没有这个设置，你可能会遇到奇怪的键位问题。装好之后，Shift+Enter 就能让你在 prompt 里换行：

hello,
and then press Shift+Enter here
you can write multi-line prompts

这对给 agent 编写更复杂的指令来说必不可少。

在 Claude Code 中用 Shift+Enter 输入多行 prompt

查看你的用量（Checking Your Usage）

想知道你的套餐还剩多少额度，运行 /usage 命令：

/usage

用量显示界面：context window 限额与当前 session 的 token

它会告诉你：

  • 当前 session（会话）还剩多少用量
  • 你的每周限额
  • 相对该限额你目前的用量

具体的数字和标签可能因套餐而异，也可能随 agent 版本变化。但这就是你随时查看剩余额度的方法。

一旦用完了你的用量窗口，在限额重置之前，你就无法继续使用 agent。

按 Escape 退出用量视图，回到聊天界面。

可视化你的 context window（Visualizing Your Context Window）

运行 /context 命令，看看你的 context window（上下文窗口）里现在装着什么：

/context

context 可视化：system prompt、skills 与消息的 token 分布

在调试配置时，这个展示非常有用。你可以看到：

  • System prompt tokens：发给 agent 的指令
  • Skills tokens：你添加的自定义 skills（技能）
  • Message tokens：对话历史
  • Context window size：总 token 容量（例如 Claude 3.5 Opus 有 100 万 token）

理解是什么填满了你的 context window，是高效使用 agent 的关键。本课程会一路深入探讨 context（上下文）管理。

清空 context（Clearing The Context）

要重置 context window、从头开始，运行 /clear：

/clear

清空后的 context window：token 数大幅减少

这会移除当前对话里的所有消息，还你一张白纸。你可以再运行一次 /context 来验证它确实生效了。

对比前后的 token 数：

状态 大致 token 数
有对话历史 ~9,000
/clear 之后 ~6,600

这说明 model（模型）是 stateless（无状态）的。一旦清空 context，agent 对你之前的对话就一无所知。

另外，你也可以按两次 Ctrl+C 退出，再开一个全新的 session。这同样会给你一个干净的 context window，对之前的对话毫无记忆。

打断 agent（Interrupting The Agent）

有时你需要在 agent 运行途中叫停它。按 Escape 打断：

explore the code base

如果 agent 开始干活之后你决定要它停下，只需按 Escape。agent 会取消它正在做的一切。

按下 Escape 后 Claude Code 显示 interrupted 消息

打断之后，context window 里会出现一条 interrupted 消息，询问接下来该让 Claude 做什么。然后你可以给它新的方向，或者让它继续。

你也可能在错误的时机按下 Escape，不小心触发打断。如果发生了，只需输入：

carry on

agent 就会从上次停下的地方继续。

小结（Summary）

你已经学会了使用 Claude Code 的必备命令：

  • 打开并聊天：在终端里启动 agent，像任何聊天应用一样输入消息
  • 多行输入：用 Shift+Enter 编写复杂的多行 prompt
  • 查看限额：运行 /usage 查看剩余额度
  • 检视 context：运行 /context，可视化查看 context window 里填了什么
  • 重置：运行 /clear，以全新的 context 从头开始
  • 打断：按 Escape 在运行途中停下 agent，再给它新的指示

你已经准备好开始与 agent 协作了。干得漂亮，我们下一节见。

# 在终端里写 prompt（Prompting in the Terminal）

了解了 prompting 的基础之后，这里有一些内置功能，可以改善你与 agent 协作的方式。

用 @ 引用文件（Referencing Files With @）

你可能想在 agent 里引用单个文件。为此，按 @ 打开文件选择器。

Claude Code 界面：@ 文件选择器以模糊搜索过滤项目文件

接下来你可以：

  • 用方向键浏览文件
  • 输入文字模糊搜索特定文件，比如 routes.ts
  • 按 return 把该文件拉进你的文本框

你可以用这种方式添加多个文件——重复这个过程就行。比如，你可以在 drizzle.config.ts 之后再添加 components.json。你也可以用 tab 把文件拉进文本窗口。

一旦按下 enter，两个文件都会立刻被读入 context window。agent 在第一次请求时就会直接读到这些文件，无需额外的 tool call（工具调用）。

当你需要传入一份 spec（规格）或某个 agent 应当直接参考的配置文件时，这尤其有用。

用 Ctrl+S 暂存 prompt（Stashing A Prompt With Ctrl+S）

有时你还没准备好发送某个 prompt，但又不想丢掉它。这时可以把它暂存（stash）起来。

输入你的 prompt——比如 "hello, how are you"

如果还没准备好发送，按 Ctrl+S 把它暂存。

agent 界面显示 prompt 已暂存的标记

你会看到一个 "stashed" 指示。现在你可以在文本框里输入别的内容。等你准备好了，被暂存的 prompt 会重新回到你的输入框里。

举个例子：

  • 暂存："hello, how are you"
  • 输入新内容："hello"
  • 按 return
  • 原本暂存的 prompt 被恢复到文本框里

在给 agent 反馈时这特别有用。你可能发了点什么，随即意识到还没准备好，收回来，在中间插入别的内容，然后再定稿你的 prompt 发出去。

粘贴图片（Pasting In Images）

你可以把图片直接复制粘贴给 agent——截图也行。

浏览器里显示着 Wikipedia 上斯洛文尼亚布莱德湖（Lake Bled）的图片

比如，这是一张斯洛文尼亚布莱德湖的图片。右键点击图片并复制，然后粘贴进文本框。你会在左下角看到一个 "pasting" 指示，图片随后出现在你的输入里。

图片粘贴进文本框后的 agent 界面

现在你可以就这张图片询问 agent。它会分析图片并给出回应。

agent 回应布莱德湖的细节，提到圣母升天教堂及其钟楼

图片会成为你 prompt 的一部分，所以你可以直接引用截图、设计稿和其他视觉素材，无需单独上传。

小结（Summary）

你现在掌握了三个强大的 prompting 技巧：

  • 引用文件：用 @ 把特定文件拉进 context
  • 暂存 prompt：用 Ctrl+S 保存写到一半的 prompt，稍后再恢复
  • 粘贴图片：把剪贴板里的图片贴进 prompt，纳入截图和视觉素材

# Claude 与你的 IDE（Claude and Your IDE）

Claude Code 通过 /ide 命令与你选择的编辑器集成。你不必像本课程这样用 VS Code——用 Cursor、Windsurf、Antigravity 或任何你可用的工具都行。

/ide 命令让你管理 IDE 集成并检查它们的状态。

/ide

运行这条命令时，它会显示你连接的是哪个编辑器。

终端显示 Visual Studio Code 连接状态

这里我们连接的是 Visual Studio Code，因为已经安装了 Claude Code for VS Code 扩展。

编辑器中已安装 Claude Code for VS Code 扩展

如果你在终端里运行 /ide，它会告诉你如何为你在用的 IDE 安装对应的扩展。

确认并退出该命令后，你就可以开始使用这个集成功能了。

在编辑器里审查 diff（Reviewing Diffs in Your Editor）

连接编辑器的主要理由是管理 diff。与 agent 协作时，这件事会不断出现。

比如，如果你让 agent「从 package.json 里移除 test watch 命令」，它会读取该文件并进行修改。

没有编辑器连接时，diff 只能以文本形式显示在终端里，别扭又难审查。而连接了编辑器之后，diff 直接显示在你的 IDE 里。

这就好用多了。你可以：

  • 滚动查看整个文件，了解上下文
  • 审查 agent 做出的确切改动
  • 用 "Accept Proposed Changes" 按钮接受所有改动
  • 点进 diff，在保存前手动微调
  • 保存文件以确认改动

在 VS Code 的 diff 视图中审查那次不错的改动

能在编辑器里深入查看并微调 agent 的输出，非常强大。而且在一个正经的 IDE 里而不是终端里审查 diff，让整个工作流顺畅得多。

为什么要用编辑器？（Why Use an Editor?）

编辑器与 agent 集成还有更多功能和更多方式，但 diff 功能是你 99% 的时间都会用到的那一个。这也是在编辑器里运行 agent、而不只是在终端里运行的首要理由。

在时间中前进与后退（Going Forwards and Backwards in Time）

agent 允许你做的一件非常重要的事，是在对话中前后穿梭。当你想先试试某个东西、之后又想撤销时，这一点至关重要。

撤销改动（Reverting Changes）

在上一个视频里，你做了一个改动，移除了一条 dev script。现在你可以直接对 agent 说：

revert that, please

agent 会通过重写并重新加回内容来撤销这次改动。你按 Control S 保存 diff，即可接受。

但还有一个更强大的选项——rewind mode（回退模式）。

使用 rewind mode（Using Rewind Mode）

快速连按两次 Escape 进入 rewind mode。在这个模式里，你可以把代码和对话恢复到 session 中的任何一个更早的时点。

比如，如果你想撤销刚才做的那条命令，可以选择上一个 checkpoint（检查点）。最下面那个是你当前的状态，它上面那个是你刚说过 "revert that please" 的时点。

用 Enter 选中它。

rewind mode 界面显示 checkpoint 历史

选择要恢复什么（Choosing What to Restore）

现在你有几个不同的选项：

选项 作用
恢复代码和对话 把整个 session 回退到这次代码改动之前的时点
恢复对话但保留代码 回退对话的同时保留你当前的代码状态
恢复代码但保留对话 回退代码的同时保留你的对话历史

你最常用到的选项是完整恢复代码和对话。一旦这么做，代码就被回退，你回到了之前那个状态所在的时点。

如果想回退得更远，再按两次 Escape 打开 rewind mode，选择更早的 checkpoint。你可以沿着 session 的整个历史一步步向后走。

还有一个 summarize from here 命令可用，但那是以后的话题。想取消 rewind mode 的话，直接选择 "nevermind"，保持当前状态即可。

rewind mode 显示多个可供导航的 checkpoint

session 的持久化与恢复（Persisting and Resuming Sessions）

另一件非常重要的事是：agent 实际上会把 session 持久化保存在本地。这意味着你可以按两次 Ctrl C 退出，然后再用多种方式恢复。

方式一：用 UUID 恢复（Option 1: Resume with UUID）

退出时，输出里会显示一条你可以直接运行的命令：

claude --resume [UUID]

直接运行这条命令，你就会回到之前离开时的确切状态。

方式二：在全新 session 里恢复（Option 2: Resume in a Fresh Session）

另外，你也可以按两次 Ctrl C 退出，然后输入以下内容打开一个新 session：

claude

这会打开一个完全崭新的 session。在里面你可以输入：

/resume

现在你会看到你在这个仓库里进行过的所有对话。你甚至可以按需搜索所有 session。选中你刚才用的那一个，按 Return 回到同一个 session。

resume 菜单显示以往 session 列表

方式三：继续上一个 session（Option 3: Continue the Previous Session）

如果你的 session 因任何原因被打断，你随时可以恢复它，因为 agent 会把 session 持久化到本地。

从上次停下的地方继续，还有另一种方式：运行

claude --continue

这会直接把你带回刚才所在的位置，无需经过 resume 菜单。

小结（Summary）

agent 允许你用以下几种方式在对话中前后穿梭：

  • 进入 rewind mode——按两次 Escape，快速浏览所有 checkpoint
  • 选择要恢复什么——决定回退代码、对话，还是两者都回退
  • 本地持久化 session——退出再恢复，不丢进度
  • 多种恢复方式——用 --continue、/resume 或 UUID 命令

有了这些工具，你可以放心大胆地试验，因为你知道随时都能退回到 session 里的任何一个之前的时点。

# 运行 bash 命令（Running Bash Commands）

使用 Claude Code 时有一个极其重要的部分：运行 bash 命令。bash 命令能把你的 agent 从一个被动的代码写手，变成一个能真正寻求 feedback loop（反馈循环）、能真正与你的项目打交道、并能随意调动 bash 全部威力来查信息、干实事的存在。

当然，你大可以直接用自然语言让 Claude「好，帮我跑一下 dev server」——它相当聪明，会自己理解「好，我需要读一下 package.json，找到 dev server 在哪，然后照这样跑起来」。但话说回来，有些时候你就是知道想运行哪条命令，只想直接跑掉，然后把结果放进 agent 的 context。

在 agent 里运行 bash 命令，实际上有三种主要方式：

  1. 直接运行命令，让 agent 看到输出
  2. 把长时间运行的进程放到后台并加以监控
  3. 挂起 agent，运行它看不到的命令

用 bash mode 运行命令（Running commands with bash mode）

运行 agent 看得到的命令，靠的是 bash mode。我刚重启了我的 agent 实例。只要敲一个感叹号，现在我就进入了 bash mode。

终端显示用 ! 前缀进入 bash mode

!

你在这里输入的任何内容都会变成 bash 命令，并真正为 agent 运行。比如，你可以在里面运行 npm run typecheck，按下 enter 之后命令就执行了。

终端显示在 bash mode 中用 ! 前缀执行 npm run typecheck

由于我在这个环境里还没运行过 npm install，冒出了一堆错误。这些错误现在就以 context 的形式呈现在 agent 面前。接下来我会让它帮我解决这些错误，它能看见这些错误并实际着手处理。

它发现 Zod 在 package.json 里，但没有安装。于是它建议你运行 npm install。这就搞定了。

把长时间运行的进程放到后台（Backgrounding long-running processes）

这对那些有始有终的命令很有效。但那些需要一直运行的命令怎么办，比如长时间运行的 dev server？

对此，你可以在 bash mode 里运行 npm run dev：

! npm run dev

在它运行期间，你可以按 Ctrl-B 把它放到后台。在这个版本的 Claude Code 里，会出现一条提示："command was manually backgrounded with userID this."

确认命令已被用 userID 手动放到后台的消息

该任务的任何输出都会写进一个本地文件。你会看到状态行下方出现了一个小小的后台任务。你可以在那里用向下箭头往下进入，然后按 return 查看它。现在你就能真正查看这个 shell、看看里面在发生什么。

后台任务面板显示 dev server 正运行在 localhost 5175

这里的选项很多。想停掉它可以用 X，也可以直接按左方向键返回，回到你的 agent 实例。

在调试 dev server 的问题时，这格外有用，因为 agent 能看到所有日志都写到了哪里。它可以在 UI 里尝试一些操作，或者发一个 curl 请求，然后真正看到 dev server 的输出。

挂起 agent 以运行隐藏命令（Suspending the agent to run hidden commands）

我刚重置了我的实例，这样我们就能看另一个功能：挂起 agent。比如，你想运行某个你不希望 agent 看到结果的东西，或者懒得展示给它，同时你又想保留 agent 内部的某些状态，那就可以使用 suspend（挂起）。

在这里按 Ctrl-Z，agent 就被挂起了。这意味着你现在可以随意运行任何命令。

在挂起的终端 session 里运行 echo foo

echo foo

agent 看不到这些。

运行 fg，让 agent 带着完好状态回来

想让 agent 回来，只需在这里运行 fg，你的 agent 实例就会带着全部状态回来。

如果你只想说「好，先不管 agent，随便跑我想跑的命令，然后 fg 把它带回来」，这就非常合适。

何时使用哪种方式（When to use each approach）

这件事的决策树实际上长这样：

目标 方式 快捷操作
agent 需要看到输出 使用 bash mode ! 前缀
长时间运行的进程（dev server） 用 Ctrl-B 放到后台 在 ! 命令之后
命令要对 agent 隐藏 挂起 agent Ctrl-Z，然后 fg 返回

如果你运行的 bash 命令的输出要让 agent 看见，就用感叹号进入 bash mode，再用 Ctrl-B 把它放到后台，然后管理那些后台任务。

这对 dev server 真的非常有用。你不会每次都用它，但用的时候，通常是在调试某种 dev server 问题。

但如果你想让命令对 agent 完全隐藏，用 Ctrl-Z 快速挂起就行。

注意：这些快捷键在大多数系统上都管用，但如果你用的是 Mac，可能需要换一种做法。

以上就是在你的 agent 设置里管理 bash 命令的所有方式。

# 权限（Permissions）

Commit Map（提交对照表）

make-a-schema-change

开始本课：仓库保持 migrations 练习结束时的状态

与 agent 协作时，你始终需要权衡风险与回报，尤其是你交给它多大的权力。如果你给一个 agent 无限的权力，它可能会意外做出危险的事，比如删掉你的整个文件系统。

为了降低这一风险，Claude Code 有一套非常细致的权限（permissions）模型。默认情况下，它对自己非常严格，严格限制 agent 实际能去做什么。

审批流程（The Approval Flow）

比如你让 agent 运行一条像 echo hello 这样简单的命令。由于 echo 是一条极其安全的命令，agent 认为这条命令不必询问就可以直接运行。

echo 命令无需许可直接运行

但如果你让它做诸如对项目运行 type check 这类事情，它可能就有不同的表现。它不会自动运行，而是先请求许可。

pnpm typecheck 命令的权限请求

当 agent 请求许可时，你会看到：

  • 它将要运行的确切命令
  • 它想运行这条命令的原因
  • 三个可选的响应方式

比如，当它请求运行 pnpm typecheck 时，你可能会看到它想用 react-router-typegen 和 tsc 来运行 type check。

三个权限选项：allow once、allow always 或 reject

你的三个选项是：

  1. Allow once——好，这一次允许你这么做
  2. Allow always——好，而且从现在起，允许你在本项目里运行任何 pnpm typecheck 命令
  3. Reject and suggest——不行，而且你可以建议改用别的命令

如果你不想让 agent 运行某条特定命令，可以拒绝并建议替代方案。比如，你更想用 npx tsc 而不是 pnpm typecheck，可以按 Tab 并给出这个理由。

用 npx tsc 建议替代命令

然后 agent 会询问能否改运行 npx tsc。如果你用 "allow always" 批准，你会看到类似 Bash(npx tsc *) 的条目被加进你的 permissions。

在 settings 里编辑权限（Editing Permissions in Settings）

你的权限偏好记录在 .claude/settings.local.json 文件里。

.claude 文件夹中的 settings.local.json 文件

这里的语法值得好好理解。你完全可以提前自己编辑这个文件，允许某些操作在这个仓库里直接发生，不必每次都批准。

想允许某条特定命令，就把它加进 allow 数组：

{
"permissions": {
"allow": [
"Bash(pnpm typecheck)"
]
}
}

想声明所有 pnpm 命令都可用，可以用通配符：

{
"permissions": {
"allow": [
"Bash(pnpm *)"
]
}
}

你也可以用 deny 数组禁止 agent 做某些事。

比如，如果你不想让它运行 git push，可以禁止所有 git push 命令：

{
"permissions": {
"deny": [
"Bash(git push *)"
]
}
}

bash 之外的权限（Permissions Beyond Bash）

agent 需要许可才能运行的不只是 bash 命令。agent 还可以搜索网络、抓取网页，来佐证它在本地看到的东西。

比如，你可能让它从网上获取关于 react-router-typegen 的信息。agent 会请求你批准一次针对 "React router typegen" 的网络搜索。

网络搜索的权限请求

如果你选择同意且不再询问，agent 会把它加进 settings.local.json，并从 ReactRouter.com 之类的网站抓取内容。

从 ReactRouter.com 网站抓取内容

这条权限会以 WebFetch(domain:reactrouter.com) 的形式加进你的 settings 文件。

抓到信息后，它就能基于真实文档给你总结 React Router typegen 的工作原理。

与团队共享权限（Sharing Permissions With Your Team）

默认情况下，settings.local.json 在你的项目里，且被版本控制忽略。这意味着这些权限只对你生效。

但如果你想把这些权限共享给团队，让一组特定的操作在仓库里始终被允许，可以把 settings.local.json 重命名为 settings.json。

这样这个文件就能提交进版本控制，与团队共享。

团队里任何人在这个仓库上运行 agent，都会自动读到这些权限。对第一次接触你仓库的人来说，这强大得不可思议。他们只需运行 agent，它就已经知道这个仓库里允许做什么。这比每次都手动配置权限快得多。

auto mode 与手动权限处理（Auto Mode vs Manual Permission Handling）

还有另一种处理权限的方式：auto mode（自动模式）。你可以在 Claude Code 左下角看到模式选择器，用 Shift+Tab 在各模式之间循环切换。

模式选择器显示 manual、edits、plan 和 auto 模式

可用的模式有：

  • Manual mode（手动模式）
  • Edits mode（编辑模式）
  • Plan mode（计划模式）
  • Auto mode（自动模式）

Auto mode 使用一个 LLM 分类器来查看你的对话，检查 agent 即将运行的东西是否安全。比如，你运行 npm run typecheck，agent 会直接运行这条 shell 命令，而不先请求许可。

在 auto mode 中运行 npm run typecheck，无权限提示

这与 manual mode 不同。agent 能自己判断命令危险与否。这确实意味着要花一些 token 来检查命令是否安全，也就多花一点时间。所以 auto mode 会稍微慢一点，但好处是你几乎不用干预就能让这些事情跑起来。

主分类器 model 大概率是 Claude Haiku。不过，这个分类器并不完美。它确实会放行一些你不希望发生的事（比如有时会去迁移数据库），也会拦下一些你确实想做的事（比如创建 GitHub issue）。

但对大多数使用场景来说，它的表现还是站在「没问题」这一边的。它确实能拦住大部分会发生的坏事，尤其是那些无论如何都是坏事的东西，比如对你的文件系统执行 rm -rf。它也不会把你的用量限额推得太高，因此是一个相当不错的取舍。

在 auto mode 下，settings.json 文件依然非常有用。agent 会先检查 settings.json，然后才把命令交给分类器处理。这意味着只要在 settings.json 里写好条目，你就能给常用操作提速，不必再操心分类器。

要把 auto mode 设为默认，进入 config 并选择 default permission mode。按 Enter 或 Space 即可选中。

config 菜单显示 default permission mode 设置
