## 一个心法:流程就是 agent 的记忆

Matt Pocock 的出发点是:你手边有一群「中等到良好」的工程师(agent),它们有个致命缺陷——**没有记忆**。不记得做过什么,每次都是新的。所以你不能靠默契,只能靠**极其明确、每次都一样的流程**来让它们干出有用的活。skills 就是把流程写下来,让 AI 每次都走同一条严格的路。<Cite>(来源:[5 agent skills I use every day](https://www.aihero.dev/5-agent-skills-i-use-every-day))</Cite>

这句话解释了整套体系的设计:为什么先访谈再写 spec,为什么 spec 要拆成工单,为什么实现必须测试先行——每一步都是在给没有记忆的工人补上「上次说到哪了」。

## 主流程:idea → ship 的五步

这是整套体系的主干。每个技能吃进上一步的产物,吐出下一步的原料:

<Flow>
  <Step cmd="/grill-with-docs">
    把你访谈到共识为止(每次 grilling 可能 16~50 个问题),决策顺手沉淀进 CONTEXT.md / ADR
  </Step>
  <Step cmd="/to-spec">
    把已达成的共识写成 spec(含 user stories),发布到 issue tracker。注意:它**不再访谈你**,访谈在上一轮已经完成
  </Step>
  <Step cmd="/to-tickets">
    把 spec 拆成 tracer-bullet 工单:每张都是打通所有层的薄竖切片,并声明 blocking 关系,可以多 agent 并行认领
  </Step>
  <Step cmd="/implement">
    按工单写代码:内部驱动 `/tdd`(红-绿-重构),收尾自动跑 `/code-review`
  </Step>
  <Step cmd="/code-review">
    两轴审查:Standards 轴(代码规范 + Fowler 坏味道基线)与 Spec 轴(是否忠实实现来源 spec),并行子 agent 执行
  </Step>
</Flow>

  流程顺序来源:[aihero.dev/skills](https://www.aihero.dev/skills) The Main Flow
  模块;各步骤细节来源:[5 agent skills I use every day](https://www.aihero.dev/5-agent-skills-i-use-every-day)。

## 主流程底下:参考层 Reference

有四个技能你很少直接敲,它们是被上面调用的**公共层**:

- `/tdd` — 被 `/implement` 驱动
- `/grilling` — 被 `/grill-me`、`/grill-with-docs` 等一切访谈类技能复用
- `/domain-modeling` — 被 `/grill-with-docs` 调用,同步维护 CONTEXT.md 和 ADR
- `/codebase-design` — deep module 的共同词汇,贯穿全部

这意味着:当你直接用 `/grill-me` 时,实际运行的是 `/grilling` 的方法;当你 `/implement` 时,内部走的是 `/tdd`。理解这一点,你就明白为什么文档说「参考层是被其他技能调用的可复用层」。<Cite>(来源:本地插件 engineering/README.md,见 [GitHub 仓库](https://github.com/mattpocock/skills))</Cite>

## 一个必须记住的二分:user-invoked vs model-invoked

engineering 和 productivity 两个 README 把技能分成两类:

| 类型          | 怎么触发                                        | 例子                                                            |
| ------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| user-invoked  | 只有你主动敲 `/技能名` 才会运行,模型不会自己拉进来 | `/grill-me`、`/to-spec`、`/implement`、`/triage`、`/ask-matt`    |
| model-invoked | 模型可以根据语境自己触发,你也可以手动敲           | `/tdd`、`/prototype`、`/research`、`/code-review`、`/domain-modeling` |

推论:主流程的骨架(访谈→spec→工单→实现→审查)几乎全是 user-invoked——**节奏由你掌握**。你不说,agent 不会擅自开始写 spec。

## 合上页面,回忆一遍

测验做完后,做一次**不看资料的回忆**(这是让记忆长存的检索练习,比重读有效得多):拿一张纸,画出主流程五步,并给每步标注「输入 → 产物」。画完再[对照速查图](/reference/skill-flow-map)检查。

间隔安排:第一次学完后的第 1、3、7 天各回来重做一次上面的测验。每次 2 分钟,这比一次学一小时更能把路由能力焊进长期记忆。
